### Research
Each investigation is a question, a derivation, code written from scratch, and measured results, including the ones that did not go my way.

| | | |
|---|---|---|
| **01** | [Re-deriving a production cycle predictor](https://ramanjitsingh-hub.github.io/01/) | The Kalman filter I shipped at FemoraAI, ported line by line. It becomes a moving average after five cycles, and a 3σ safety gate can lock it out permanently. An exact Bayesian replacement fixes both. *Synthetic data.* |
| **02** | [When is a cheap model good enough?](https://ramanjitsingh-hub.github.io/02/) | Luna sends each request to the cheapest capable model. On 44,241 prompts answered by 13 language models, a text router matches GPT-4o at about 10% of its cost, but most of the gain is recognising the task type, and on unseen task types it falls below a fixed model. Includes the decision theory, an oracle luck analysis, and a quality guarantee certified with betting martingales. *Public benchmark data.* |
| **03** | [What can a startup learn from fifty users?](https://ramanjitsingh-hub.github.io/03/) | A real retailer's whole customer base as ground truth, sampled at startup scale. With 50 users a retention rate is known to about ±11 points, and checking a test daily finds a false winner 42% of the time. Wilson intervals, empirical Bayes shrinkage and always-valid sequential tests recover much of it. *Public data.* |
| **04** | [When does mixing keyword and meaning search help?](https://ramanjitsingh-hub.github.io/04/) | The fusion behind Luna's memory search, tested on five BEIR benchmarks. The popular recipe, reciprocal rank fusion, loses to meaning search alone on three. A learned weight is never significantly worse and wins on three, and a two-signal detection model predicts the direction of an equal mix. *Public data.* |
